An AI support agent that kills one 80% problem for a niche Irish retailer.

This is the full method behind the Boru Bats chatbot: a fictional Galway slowpitch-bat shop where 8 in 10 customer messages are the same question, "is this bat legal?". Two strategist agents shaped it and the Five Innovators workflow drove it. It checks a real bat code against the official 3,646-bat approved list, and answers everything else with a live LLM behind a secure proxy. The principle: the model talks, the list decides.

The exercise: invent a fictional company in a narrow niche that depends on customer service, name a problem that hits 80% of its customers, then build a working chatbot that solves it and deploy it to a live page.

The company

Boru Bats is a specialist retailer of slowpitch softball bats serving players across the Republic of Ireland. The niche is narrow but devoted: recreational and competitive players who need bats certified legal for WBSC Europe tournament play. Boru stocks only compliant models, ships anywhere in Ireland within the week, and gives hands-on advice, weight, balance, barrel length and grip matched to each player's swing.

The 80% problem

Certification confusion. Bargain-hunters import bats from US sites carrying USA Softball or USSSA stamps, then get turned away at tournament bat-check because those marks are not recognised under WBSC Europe rules. Others cannot tell whether a worn second-hand certification stamp is still valid. The result: wasted money, pre-fixture panic, and a flood of "is this bat legal?" messages that dominate the support inbox.

The job of the bot

Take that one repeated question off the inbox, answer it correctly and kindly at any hour, and quietly route a stranded customer to a bat that will actually pass bat-check.

Before any code, two specialist agents were spawned to think the problem through, exactly as the brief suggests: one technical chatbot expert, one business-domain expert. They worked in parallel; their conclusions shaped every later decision.

Tech agent Conversational-AI engineer

Architecture call: keep the high-stakes part deterministic. The 80% problem (legality) must never be a guess, so a real bat code is matched against the official approved-bat list in the browser, no model involved. A live LLM was flagged as the right "phase 2" for natural conversation, via a server-side proxy, never with a key in the page.

What shipped is exactly that hybrid: the legality lookup runs client-side against the 3,646-bat dataset (instant, free, auditable), while a live LLM handles fitting, shipping and freeform chat through a Cloudflare Worker that holds the API key as a server-side secret. The model is Gemini 2.5 Flash on Google's free tier, no credit card. The model talks, the list decides.

The non-negotiable lesson: never hardcode an API key in front-end code. A GitHub Pages site ships every file to the browser, anyone can read it via "View Source", and the key lives in public git history forever. So the key lives only inside the Worker; the public page calls the Worker, which adds the key and forwards to the LLM.

Also specified: 7 intents weighted toward certification; quick-reply chips on every turn; a typing indicator; an always-visible "talk to a human"; and a cap of two failed inputs before auto-escalation so a panicked customer never hits a dead end.

Business agent Sports-retail & customer engagement

Tone: the knowledgeable person behind the counter in Galway, warm and plain-spoken, never the corporate help desk, and never condescending about a bad import ("easy mistake, you're far from the first").

Turn support into sales: when a customer's imported bat is not legal, acknowledge without judgement, give the verdict plainly, then pivot to the player, not the product, ask swing style and fixture date, and offer at most two compliant bats with shipping that beats their deadline. Rescued, not sold to.

Trust guardrails: the bot must never guarantee a specific bat is legal without checking the current official approved list, never confirm a worn stamp from description alone, and always defer the final word to the umpire. Any doubt routes to a human.

The one metric: assisted-conversion rate on "not legal / cert-doubt" conversations, the share of confused arrivals who leave having ordered a compliant bat or booked a fitting.

Deploy, step by step

  1. Research confirmed the legal facts and the closed allow-list approach (only WBSC Europe marks pass).
  2. Design locked the static-only architecture and the intent map from the two agents.
  3. Make wrote the index.html app, slimmed the official 3,646-bat dataset into bats.json, built a Cloudflare Worker that holds the LLM key as a secret, then git push to a public repo and enabled GitHub Pages.
  4. Market wrapped it in a positioning line and a preview card so a shared link sells itself.
  5. Manage ran the acceptance checks (below), confirmed a 200 on the live URL and a correct answer to a US-import question, then signed it off.

The list decides: real bat-code lookup

Type a model code from the barrel and the bot matches it against bats.json, a slimmed copy of the official lists (2,281 WBSC-approved, 1,888 USA Softball, 3,646 total). The verdict is exact, with the date the bat was added:

  • On the WBSC list, legal for tournament play here.
  • On the USA Softball list only, not recognised under WBSC Europe, refused at bat-check.
  • Not found, it tells you, and points to a human and the full searchable list.

Example: ASPDAW25A returns "Anarchy Shock and Dawe, USA Softball only, not legal here", because that is what the official data says. No guessing.

The model talks: a real LLM, free and kept safe

Anything that isn't a code (fitting advice, shipping, freeform questions) goes to a live LLM, Gemini 2.5 Flash on Google's free tier, through a Cloudflare Worker. The Worker holds the API key as a server-side secret and adds a Boru Bats system prompt, so the model stays in character and the key never reaches the browser. If the free rate limit is ever hit, the bot falls back to scripted answers, so it never dies, and never produces a bill.

A code detector that won't misfire

A naive "contains a number" rule would send "I'm 60 and not very strong" to the bat list and wrongly answer "not found". The detector only treats a token as a code when it is five or more characters mixing letters and digits, so ages, weights and dates flow to the LLM instead.

Acceptance checks that had to pass

  • A real USA-only code returns "not legal here" with the reason and date, verified with ASPDAW25A.
  • A real WBSC code returns "legal", verified with AXEL101.
  • A natural sentence with a number routes to the LLM, not the list.
  • The API key appears only in the Worker secret, never in the page or git history.
  • The live URL returns 200 and renders the real app (verified by screenshot).

The thing that trips up most beginners: you want real AI in your bot, but you don't want to hand over a card or risk a surprise bill. You don't have to. This whole chatbot runs on a free LLM with no payment details anywhere.

The easy free route: Google AI Studio (Gemini)

  • Go to aistudio.google.com, sign in with any Google account, and click Get API key. It's free and asks for no credit card.
  • You get a key for the Gemini models. This site uses gemini-2.5-flash, fast and free.
  • The free tier has a rate limit (a set number of requests per minute and per day). Go over it and the API simply returns an error, it never charges you. Check the current limits in AI Studio.

The whole thing in 12 lines

This is the entire call. Paste your free key and it works in any page or script:

Paste-ready · free Gemini call (JavaScript)
const KEY = "PASTE_YOUR_FREE_GEMINI_KEY"; // free at aistudio.google.com, no card const MODEL = "gemini-2.5-flash"; async function ask(message) { const res = await fetch( "https://generativelanguage.googleapis.com/v1beta/models/" + MODEL + ":generateContent?key=" + KEY, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ contents: [{ role: "user", parts: [{ text: message }] }] }) } ); const data = await res.json(); return data.candidates[0].content.parts[0].text; }

Two ways to use your free key

  • Just you, your own project: put the key straight in your page (or store it in the browser). Zero backend, simplest possible start. Rule: never commit the key to a public repo, and never put a paid key in front-end code. A free, no-card key in your own browser is fine for learning.
  • A bot anyone can use (like this one): put the key in a free Cloudflare Worker (server-side); the public page calls the Worker. Neither Cloudflare nor Gemini needs a card. This keeps the key invisible to visitors.

Other free, no-card options

  • Groq, free API, very fast, runs open models.
  • OpenRouter, offers a selection of free models.
  • Ollama, run a model on your own laptop, no key, no internet needed, totally free.
  • Hugging Face, a free inference tier.

Limits and model names change, so check each provider for what's current. One rule never changes: a key is a password. Free or paid, never hardcode it in a public page or commit it to git.
